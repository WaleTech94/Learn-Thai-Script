## 1. Architecture

- **One self-contained file:** `index.html` (vanilla JS, no build step, no frameworks, no runtime API calls). Everything — CSS, data, engines — lives in this file by deliberate choice ("single growing file").
- **Deployed as a PWA** on GitHub Pages, with Vercel also configured as a parallel static deploy target. Companion files: `manifest.json`, `sw.js` (service worker: network-first for the shell so updates propagate, cache-first for assets), `icon-180/192/512.png`, `vercel.json`.
- **Deploy loop:** commit and push to `main`; GitHub Pages rebuilds in ~60s and Vercel deploys from the same GitHub repo when its integration is connected. On iPhone: open app online, swipe closed, reopen. Version string is at the bottom of the Today tab.
- **Persistence:** `localStorage` key `thai_state_v1`, with a fallback to Codex's artifact `window.storage` when run inside Codex. Saves are debounced 350ms and **flushed synchronously on `visibilitychange`/`pagehide`** (iOS swipe-away protection). Export/Import buttons (Progress → Progress tools) download a versioned JSON backup envelope, keep a copy-to-clipboard fallback and still accept legacy raw-state JSON.
- **Audio:** browser `speechSynthesis` with the device Thai voice (iOS: Kanya). This is device voice support only: a rough model for practice, not native-speaker recording or reliable assessment evidence for tone, vowel length, aspiration or final-stop mastery. Speech is primed on first touch (iOS gesture requirement), resumed on foreground and on speaker taps, and v3.14 shows guided setup if no Thai system voice is exposed. The iPhone help distinguishes Chrome, Safari and installed-app mode, but all route to iOS system voices (`Settings → Accessibility → Read & Speak → Voices → Thai`; older iOS may say Spoken Content). No human-audio manifest, asset folder, recording pipeline, demo audio, AI audio or scraped audio exists in v6.0.0. Vowel cards label the target vowel sound, the carrier letter อ, and the full carrier form because isolated Thai vowels need a visible/speakable carrier but อ is silent in that form. v2.35 also uses `MediaRecorder` for optional, private record/playback comparison in read-aloud/contrast practice only; recordings remain local and are discarded when the learner leaves the activity. v5.4 fluency reads and the final checkpoint do not require microphone use.
- **iOS chrome:** full-bleed standalone with a fixed opaque status-bar scrim (`env(safe-area-inset-top)`), opaque tab bar with the bottom inset *outside* the fixed 64px bar height, 44pt minimum touch targets, `touch-action: manipulation` everywhere.
- **Visual identity and arcade:** v8.0.0 supplies the single-file/offline Bangkok Street Atlas shell. v8.1.0 adds three code-native theme motifs, temporary theme previews and three optional cabinets whose HTML/CSS/locally synthesized sounds inherit the active theme; class colours keep their teaching meaning and no visual, audio or runtime-network asset is added.

## 2. Content conventions (non-negotiable for continuity)

- **Transliteration — the "or" scheme** (Smyth-style, UK non-rhotic friendly): ออ = `or` (khǒr, phôr, hôrng), เ-อ = `er` (bpèrt, ter), โอ = `oh` (sôh). Tone diacritics on plain Latin vowels only: `a` mid · `à` low · `â` falling · `á` high · `ǎ` rising. These Latin tone signs are reading hints only; tone reasoning should come from Thai script: consonant class + live/dead + Thai tone mark. Doubled vowels = long. `bp`/`dt` = unaspirated. **Never use IPA ɔ or combining marks on unusual bases** — they break font fallback on iOS (caused the v2.0 rendering bug). The whole file is NFC-normalised; keep it that way (patches must NFC-normalise both sides or string matches fail).
- **Isolated vowels/tone marks display on carrier letters** (อา, อี, เอีย; tone marks on ก: ก่ ก้), the Thai-textbook convention — never on a raw dotted circle ◌. Every vowel/mark glyph has a `disp` field.
- **Consonant class colour system:** letters are class colour coded: mid = teal, high = pink, low = marigold, *everywhere*, in *every theme*. Themes may change atmosphere only. Connected Thai on teaching/reveal/practice surfaces should colour consonant letters by class, including word reads, tone examples and Thai-word MCQ options. The deliberate exception is neutral class-recall before answer (`Which class?`, `Pick the low class consonant`) because colour would give away the response.
- **Consonant final sounds are now explicit Phase-1 alphabet content (v4.1, strengthened in v4.9):** do not start this in Lesson 1, but from Lesson 2 onward teach that a consonant has a **start job** and an **ending job**. Ending jobs must appear as dedicated lesson cards, `f:` review cards and explicit quiz/checkpoint/boss/mixed-review questions, not only as a subline inside word reveals. Use the same frame everywhere: start sound + vowel + ending sound, then live/dead and tone. The start consonant gives class; the final consonant gives the ending sound and helps decide live/dead. Do not reduce finals to tone support only.
- **Structural clarity markers are explicit Phase-1 content (v4.2):** hidden vowels, front/wrap/three-piece vowel order, live/dead sound feel, short/long vowel length, and true/fake clusters should be named in decode frames when they are the useful reading mechanism. These are not side facts; they are part of how the learner learns to parse Thai script. Generated lesson checks must keep testing them directly through `validateStructuralClarityContracts()`.
- **Balanced component MCQs are the default for eligible decode and Thai-choice questions (v4.4):** a learner should not be able to answer by identifying only one component. Where covered material supports it, Mini decode / Quick decode and remaining Thai-choice surfaces such as listening/review options should preserve two live axes, such as start consonant × vowel/rime. Synthetic Thai grid options must pass taught-glyph coverage before they appear; if the full grid is not available, fall back to the misconception-ranked distractor system rather than inventing unsafe Thai content.

- **Lesson-word roles (v2.36→v6.0.0, important):** every lesson word has an explicit `vocab` role. Current split is 97 entries: 66 core, 23 recognition, 8 decode-only. `core` = useful enough for receptive meaning, objective listening and Spell it; `recognition` = useful to understand but not worth English→Thai production or spelling practice; `decode` = script scaffolding only, with meaning available on reveal but never tested. อ่าน is recognition-only and `review:false` because it is a course-name teaching moment, not extra review burden. English→Thai spoken vocabulary production is deferred beyond Phase 1; lesson speaking practice is script-cued read-aloud only. Do not infer vocabulary importance merely because a word is decodable. The legacy `util:"practice"` fallback remains in `wordRole()` for compatibility, but new lesson content must use `vocab`.

## 8. Working agreements (read before doing anything)

**Brainstorm first, build only when told.** When the owner asks about new features, directions, or "what could we do" — discuss options and seek explicit approval BEFORE touching any files. Do not start building until the owner clearly says to (e.g. "build it", "ship that", "do it"). Default to a conversation, not a commit. This is the single most important rule here.

**Push approved versioned builds.** The owner tests on the installed mobile PWA, so an unpushed local patch is not testable. Once the owner has approved a versioned app build, complete the full workflow after validation and documentation sync: commit and push to `main` unless the owner explicitly says not to.

**Separate established fact from conjecture** in any analysis or recommendation — what's evidence-backed vs. inference. The owner relies on this distinction.

**Surgical, version-locked patches** — never rewrite working code without cause. Make the smallest change that achieves the goal. The app has survived 15+ versions clean because of this.

**Validate before every commit (non-negotiable):**
- Run `node tools/precommit-check.js`; it wraps embedded-script syntax, NFC, particle/currency policy, tone-grid transliteration, Reading-room decodability and fresh-decode corpus checks.
- Run `node tools/arcade-smoke.js` for deterministic full-session checks of all three cabinets, theme preview restore and Default/Ranat/muted sound scheduling.
- Extract the embedded `<script>` and run `node --check` on it.
- Run the standalone tone/decodability validation (see section 2) for any content change. Every Thai word must be tone-verified against the standard grid before shipping. For multi-syllable phrases, check the positionally-first toned syllable.
- Never commit a build that fails either check.

**Version discipline:** bump the version string (bottom of Today tab) on every shipped change and tell the owner the expected version string so they can confirm the deploy landed.

**Documentation sync is a shipping gate (non-negotiable):** every versioned app change must update, in the same commit, **all three** documentation surfaces: `AGENTS.md` (canonical working instructions), `CHANGELOG.md` (version/date + user-visible and technical changes), and the local `CLAUDE.md` mirror when present. Update the Current state, affected architecture/pedagogy/state-schema sections, and version history—not only the changelog line. Before committing, verify the app footer version, `AGENTS.md` Current state, and newest `CHANGELOG.md` entry all match. A versioned app commit that omits these updates must not be committed or pushed. Documentation-only corrections do not require an app version bump.

**Content rules (see section 2 for detail):** male particle ครับ only; or-scheme transliteration as a reading aid; Thai-script-first tone reasoning; class-colour system; NFC-normalise patches; never rename state keys (section 5).

## 9. Deploy process (Codex)

The repo is the working directory. Codex edits files in place and deploys via git:
```bash
# after validation and documentation sync pass:
git add index.html sw.js manifest.json vercel.json AGENTS.md CLAUDE.md CHANGELOG.md README.md FILE_MANIFEST.md THAI_APP_AUDIT_PACK.md docs/ tools/
git commit -m "vX.Y.Z — <summary>"
git push
```
GitHub Pages rebuilds in ~60s. Vercel also deploys from `main` once the GitHub integration has been connected; `vercel.json` keeps it as a static/no-framework project with no build step and root output. The owner then opens the PWA on his iPhone 16 (Chrome, installed to home screen) **while online**, swipes it closed, and reopens — the service worker fetches the new shell network-first, so the second launch is fresh. Confirm the version string with the owner.

No web-upload step anymore (that was the pre-Codex workflow). Keep `manifest.json`, `sw.js`, `vercel.json`, and icons in the repo root; bump the `CACHE` constant in `sw.js` only if cached asset filenames change.
